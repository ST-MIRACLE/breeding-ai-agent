# 育种AI自动化工作流（Breeding AI Agent）

> 面向育种科研人员的AI自动化数据处理平台，解决种质实验数据人工整理耗时长、易错的痛点。

## 项目概述

针对农学育种领域大量实验数据和文献人工整理效率低下的问题，设计并实现了一套基于大语言模型的AI自动化工作流。通过专业提示词工程、知识库约束、输出校验三层机制，在保证数据准确性的前提下，将数据处理效率提升近10倍。

## 核心功能

- **实验数据结构化提取**：从原始实验记录（CSV/Excel）中自动提取标准化的种质资源数据
- **育种文献智能解析**：从科研论文PDF中提取关键实验数据、研究结论
- **知识库约束机制**：内置农学术语、字段定义、合法取值范围，约束大模型输出
- **多维度输出校验**：枚举值校验、数值范围校验、字段完整性检查，解决幻觉问题
- **批量处理支持**：支持批量处理上百份种质材料数据

## 技术架构

```
[原始实验数据] [育种文献PDF]
       |              |
       ▼              ▼
  [数据预处理]   [PDF文本提取]
       |              |
       └──────┬───────┘
              ▼
     [专业提示词模板]
              |
              ▼
     [大模型 API 调用]
              |
              ▼
    [知识库约束 + 输出校验] ← [农学知识库]
              |
              ▼
     [结构化数据输出]
```

## 技术栈

- **编程语言**：Python 3.9+
- **大模型**：通义千问 / 文心一言（支持扩展）
- **数据处理**：pandas, openpyxl
- **PDF解析**：pdfplumber / PyPDF2
- **API通信**：requests

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 运行演示（无需API Key）

```bash
python src/workflow.py --input data/raw/germplasm_data.csv --mock
```

### 3. 使用真实大模型API

```bash
# 通义千问
python src/workflow.py --input data/raw/germplasm_data.csv --api-key YOUR_API_KEY

# 文心一言
python src/workflow.py --input data/raw/germplasm_data.csv --api-key YOUR_API_KEY --provider ernie
```

### 4. 运行测试

```bash
python tests/run_tests.py
```

## 核心成果

### 效率提升
| 处理量 | 人工耗时 | AI耗时 | 效率提升 |
|--------|----------|--------|----------|
| 30份 | ~4.5小时 | ~11分钟 | 24.5x |
| 180份 | 6-7小时 | ~40分钟 | ~10x |

### 准确率提升
| 优化阶段 | 准确率 | 提升幅度 |
|----------|--------|----------|
| 基础提示词（无校验） | ~62% | - |
| + 知识库约束 + 专业提示词 | ~75% | +13% |
| + 输出校验机制 | ~83% | +8% |
| + 多轮迭代（few-shot调优） | **88%** | +5% |

### 幻觉问题解决方案

1. **第一层：知识库约束**
   - 内置字段定义、合法枚举值、数值范围
   - 提示词中注入领域知识，规范输出格式

2. **第二层：输出校验**
   - 枚举值合法性校验
   - 数值范围合理性检查
   - 字段完整性验证
   - 异常值自动标记修正

3. **第三层：迭代优化**
   - 多轮测试发现典型错误模式
   - Few-shot示例引导正确输出
   - 持续优化提示词模板

## 常见问题

**Q: 没有API Key可以运行吗？**
A: 可以，使用 `--mock` 参数即可在模拟模式下运行，用于演示和测试流程。

**Q: 支持哪些大模型？**
A: 目前支持通义千问（阿里云）和文心一言（百度），可通过扩展 llm_client.py 支持更多模型。

**Q: 可以处理其他作物的数据吗？**
A: 可以，只需修改 knowledge_base/ 下的知识库文件，适配对应作物的字段定义即可。
